# The Photovibe website

[photovibe.mory.dev](https://photovibe.mory.dev) is a static [Astro](https://astro.build)
site in [`site/`](../site). It is intentionally its own project with its own
`package.json` and lockfile, so working on the website never disturbs the desktop app.

## Run it

```bash
cd site
pnpm install
pnpm dev        # http://localhost:4321
pnpm build      # astro check && astro build -> site/dist
pnpm preview    # serve the built output
```

## Layout

```
site/
  astro.config.mjs          site URL, sitemap integration, Tailwind
  src/consts.ts             tool list, blend modes, works-today / coming-next
  src/faq.ts                comparison-page FAQ, also the FAQPage schema source
  src/components/
    SeoHead.astro           canonical, Open Graph, Twitter, JSON-LD @graph
    Screenshot.astro        responsive 1x/2x WebP figure
    DownloadButton.astro    resolves the newest signed installer at runtime
    Header.astro Footer.astro
  src/layouts/
    Base.astro              page shell
    Doc.astro               docs shell: sidebar, breadcrumbs, prev/next
  src/pages/
    index.astro                    landing
    download.astro                 download + verification
    photoshop-alternative.astro    comparison page and FAQ
    docs/index.astro, docs/[...slug].astro
    404.astro
  src/content/docs/*.md     the documentation, a content collection
  src/assets/samples/       photos used *inside* the editor in screenshots
  scripts/                  screenshot + Open Graph capture
  public/screenshots/       generated, committed
```

### Copy that must not drift

`src/consts.ts` mirrors real values from the app — the twelve tools and their shortcuts
from `src/components/Toolbar.tsx`, the thirteen blend modes from
`src/engine/document/types.ts`, and the works-today / coming-next lists from which menu
items are enabled in `src/app/AppShell.tsx`. When you enable a menu item in the app, move
the matching line from `COMING_NEXT` to `WORKS_TODAY` and update
`site/src/content/docs/roadmap.md`.

## Screenshots

Every screenshot on the site is the real editor, captured automatically:

```bash
cd site
pnpm capture             # all scenes plus the Open Graph card
pnpm capture hero        # just one scene
pnpm capture og          # just the Open Graph card (no app needed)
```

`scripts/capture-screenshots.mjs` starts `pnpm dev` at the repo root, drives the app in
headless Chromium through genuine interactions, and writes 1x and 2x WebP into
`public/screenshots/`. Two details make this work:

- `tauri.conf.json` sets `"decorations": false`, so the window chrome is the app's own
  HTML — a browser capture looks identical to the desktop window.
- `AppShell.handleOpen` falls back to a browser `<input type="file">` when Tauri is
  absent, which is how a real photo gets onto the canvas.

Scenes live in the `scenes` object in that script. Add one there and it is picked up
automatically.

The sample photos in `src/assets/samples/` are Unsplash-licensed and credited in
`CREDITS.md`. They are not part of the application and are never shipped with it —
replace them with your own JPEGs of the same names and re-run `pnpm capture`.

**Re-run the capture after any visible UI change.** Stale screenshots are the fastest way
for the documentation to start lying.

## SEO

- Canonical URL, Open Graph and Twitter tags on every page via `SeoHead.astro`.
- JSON-LD `@graph`: `WebSite` and `Organization` site-wide, plus `SoftwareApplication`
  on the landing and download pages, `FAQPage` on the comparison page, and
  `BreadcrumbList` + `TechArticle` on docs pages.
- `sitemap-index.xml` generated by `@astrojs/sitemap`; `public/robots.txt` points at it.
- The Open Graph card is generated from `scripts/og-template.html`, so it always shows a
  current screenshot.

## Deployment

Vercel builds the site from this repository with **Root Directory `site`**, and serves it
at `photovibe.mory.dev`. Because `mory.dev` uses Vercel DNS
(`ns1.vercel-dns.com` / `ns2.vercel-dns.com`), adding the domain to the project creates the
record and certificate automatically.

Vercel's default *Automatic* ignored-build-step skips a rebuild when a commit touches
nothing inside `site/`, so ordinary app commits do not redeploy the website.

```
push to master ─┬─> ci.yml      pnpm test + tsc --noEmit
                ├─> site.yml    astro build, only when site/** changed
                └─> Vercel      root=site -> photovibe.mory.dev

tag v0.1.0 ─────> release.yml   tauri build -> Azure Trusted Signing
                                -> SHA256SUMS -> GitHub Release
                                      ^
                                      └── the download button reads this
```

The download button has no build-time dependency on releases: it fetches
`api.github.com/repos/mory-dev/photovibe/releases/latest` in the browser and falls back to
the releases page, so the site is correct both before and after the first release.
